# PRD: 가족 보험 청구 참고 조회기

## 1. 배경

가족이 가입한 보험이 여러 개 있을 경우, 병원 진료 후 어떤 보험에 청구해야 하는지 확인하기 어렵다. 보험 약관, 보험 조회 화면, 진단서, 진료비 영수증, 약제비 영수증, 실제 지급 결과가 서로 흩어져 있으면 반복 청구 시 같은 확인 작업을 다시 해야 한다.

이 프로젝트는 가족 보험과 병원 서류를 로컬에 정리하고, 병원비 청구 전 참고할 수 있는 담보 후보를 조회하는 개인용 도구를 만든다.

---

## 2. 목표

### 핵심 목표

- 가족 보험 목록을 로컬에서 관리한다.
- 약관과 증권 문서를 로컬에서 연결한다.
- 병원 서류 이미지를 로컬 OCR로 읽어 입력 부담을 줄인다.
- OCR 결과는 사용자가 확인 후 저장한다.
- 진단코드, 통원/입원, 약제비, 수술 여부 기준으로 해당 가능 담보를 조회한다.
- 과거 청구 이력과 실제 지급 결과를 함께 보여준다.
- 미청구 가능성과 입금 확인 필요 건을 표시한다.

### 비목표

- 보험금 지급 가능 여부를 확정하지 않는다.
- 보험사 API에 직접 연결하지 않는다.
- 마이데이터 자동 연동을 하지 않는다.
- 외부 AI 분석을 하지 않는다.
- 클라우드 OCR을 사용하지 않는다.
- 고객 관리 시스템을 만들지 않는다.

---

## 3. 사용자

### 주 사용자

가족 보험을 관리하는 일반 사용자.

### 사용자 특성

- 보험 전문가가 아니다.
- 보험 약관을 모두 수기로 입력하기 어렵다.
- 병원 청구 시 어떤 보험을 확인해야 하는지 빠르게 알고 싶다.
- 개인정보가 외부로 나가는 것을 원하지 않는다.
- 실제 개발 전 화면과 흐름을 먼저 확인하고 싶다.

---

## 4. 핵심 사용 시나리오

### 시나리오 1: 보험 목록 반자동 등록

1. 사용자가 내보험찾아줌, 네이버페이, 토스, 보험사 앱의 보험 조회 화면을 캡처한다.
2. 앱에 이미지를 등록한다.
3. 로컬 OCR이 보험사명, 상품명, 피보험자, 계약상태, 보험기간 후보를 추출한다.
4. 사용자가 후보값을 확인·수정한다.
5. 보험 목록에 저장한다.

### 시나리오 2: 약관에서 담보 후보 등록

1. 사용자가 약관 PDF 또는 DOCX를 등록한다.
2. 앱이 텍스트를 추출한다.
3. 앱이 담보명, 지급사유, 보상하지 않는 손해, 한도, 공제금액 후보를 찾는다.
4. 사용자가 필요한 담보만 확인 후 등록한다.

### 시나리오 3: 병원 서류 OCR 후 청구 사건 생성

1. 사용자가 진단서, 영수증, 약제비 영수증 이미지를 등록한다.
2. 앱이 로컬 OCR을 수행한다.
3. 앱이 진료일, 병원명, 진단코드, 진단명, 금액 후보를 표시한다.
4. 사용자가 수정 후 확정한다.
5. 앱이 청구 사건을 생성한다.

### 시나리오 4: 청구 참고 조회

1. 사용자가 가족 구성원과 진단코드, 통원/입원, 약제비 여부를 입력한다.
2. 앱이 등록된 담보 규칙과 과거 청구 이력을 조회한다.
3. 결과를 `해당 가능 담보`, `확인 필요 담보`, `현재 조건과 불일치`로 구분해 표시한다.
4. 사용자는 약관 원문과 과거 청구 결과를 확인한다.

### 시나리오 5: 지급 결과 관리

1. 사용자가 보험사별 실제 지급 결과를 입력한다.
2. 앱은 청구 이력과 지급 결과를 연결한다.
3. 다음 유사 청구 시 과거 지급 사례를 보여준다.

## 5. 보안 요구사항

| 항목 | 요구사항 |
|---|---|
| 데이터 저장 | 로컬 저장 |
| 외부 전송 | 기본값 없음 |
| OCR | 로컬 OCR만 허용 |
| AI 분석 | 외부 AI 금지 |
| 계좌번호 | 저장하지 않음 |
| 주민번호 | 저장하지 않음 |
| 카드번호 | 저장하지 않음 |
| 증권번호 | 전체 저장 지양, 마스킹 우선 |
| 원본 문서 | 로컬 attachments 폴더 저장 |
| 백업 | 암호화 백업 권장 |

## 6. 성공 기준

1차 MVP 성공 기준은 다음과 같다.

- 가족 구성원과 보험을 등록할 수 있다.
- 보험 조회 캡처에서 보험 후보 정보를 추출할 수 있다.
- 약관 PDF/DOCX에서 담보 후보를 찾을 수 있다.
- 진단서/영수증 OCR 결과를 사용자 확인 후 저장할 수 있다.
- 하나의 청구 사건에 여러 보험사 청구 이력을 연결할 수 있다.
- 실제 지급 결과를 청구 이력에 연결할 수 있다.
- 진단코드와 통원/입원 조건으로 해당 가능 담보를 조회할 수 있다.
- 미청구 가능성과 입금 확인 필요 건을 표시할 수 있다.

---

## 7. MVP 제외 범위

- 모바일 앱
- 클라우드 동기화
- 자동 보험사 청구
- 보험금 자동 산정 확정
- 보험사 API 연동
- 마이데이터 API 연동
- 상담원/고객 관리 기능
- 다중 사용자 권한 관리
- 외부 AI 분석
- 클라우드 OCR
