# 개발 전 로컬 시각화 기준선

## 1. 목적

이 문서는 Figma, FigJam, Manyfast 없이도 `FamilyClaimRef`의 화면 구조와 흐름을 검토하기 위한 로컬 시각화 기준선이다.

현재 단계는 app 개발이 아니다. 이 산출물은 구현 전 검토용 정적 문서와 Low-Fi HTML 와이어프레임이며, DB, OCR, PDF/DOCX 파서, runtime 서버, 실제 기능 동작을 포함하지 않는다.

## 4. 화면 범위

이번 시각화 기준선은 다음 화면을 포함한다.

- 홈 대시보드
- 가족 구성원
- 보험 목록
- 보험 상세
- 문서함
- OCR 확인함
- 청구 사건
- 보험사별 청구 이력
- 청구 참고 조회 결과

## 5. 익명 샘플 데이터 원칙

시각화에는 실제 개인정보, 실제 보험사명, 실제 병원명, 실제 가족 실명을 사용하지 않는다.

허용되는 표기 예시는 다음과 같다.

- `가족 A`
- `가족 B`
- `보험사 A`
- `보험사 B`
- `병원 A`
- `문서 A`
- `청구 사건 A`

## 6. 민감정보 취급 기준

다음 항목은 화면 설계 단계에서도 민감정보로 취급한다.

- 가족 구성원 이름, 생년월일, 관계
- 보험 계약 정보, 증권번호, 특약 정보
- 병원 문서, 진단명, 진료일, 영수증 금액
- 청구 이력, 지급 결과, 미지급 사유
- OCR 후보값과 사용자가 확정한 값

Low-Fi 와이어프레임은 민감정보가 어느 화면에서 입력, 저장, 조회되는지만 표시하고 실제 값을 만들지 않는다.

## 7. 개발 전 게이트

개발 시작 전 다음 항목을 확인해야 한다.

- IA에서 누락된 핵심 화면이 없는가
- 사용자 흐름이 실제 청구 준비 절차와 맞는가
- 상태 흐름에 되돌림, 보류, 수정 상태가 필요한가
- 각 화면의 입력값, 저장값, 조회값이 구분되어 있는가
- 민감정보가 Git 추적 제외 경로에만 저장되도록 설계되어 있는가
- `attachments/`와 `data/local/` 내부에 실제 또는 샘플 개인정보 파일이 없는가

## 8. 금지 범위

이 기준선 작성 단계에서는 다음을 하지 않는다.

- `app/` 생성
- `src/` 생성
- `package.json` 생성
- `tsconfig.json` 생성
- DB 구현
- OCR 구현
- PDF/DOCX 파서 구현
- runtime 서버 구현
- 실제 개인정보 샘플 생성
- 실제 보험사명, 병원명, 가족 실명 사용
