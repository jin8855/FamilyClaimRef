# 화면 검토 체크리스트

## 1. 목적

이 문서는 V5.5 정적 Low-Fi 와이어프레임을 브라우저로 검토할 때 확인할 항목을 정리한다. 실제 기능 구현 여부가 아니라 개발 전 시각화 기준의 일관성을 확인한다.

## 2. 공통 체크

- 모든 화면 header가 왼쪽 제목, 오른쪽 breadcrumb 구조인가
- breadcrumb의 홈 링크가 `index.html`로 연결되는가
- 청구 흐름 단계바가 5단계로 일관되는가
- JavaScript, 외부 CDN, 외부 CSS 링크, 외부 폰트 링크가 없는가
- 실제 개인정보, 실제 가족 실명, 실제 보험사명, 실제 병원명이 없는가
- 실제 진단코드 기반 개인 사례가 없는가

## 3. V5.5 액션 정렬 체크

- 다음 작업 영역은 타이틀 왼쪽, 버튼 오른쪽 구조인가
- 패널 타이틀 영역이 과하게 커지지 않는가
- 보험 상세 화면에 닫기 버튼이 있고 보험 검색으로 돌아가는가
- 보험 검색의 검색 조건 오른쪽에 홈 버튼이 있는가
- 이력 보기의 검색 조건 오른쪽에 홈 버튼이 있는가
- 이력 목록의 보기 버튼이 이력 상세 화면으로 이동하는가
- 이력 상세 화면이 존재하는가
- 등록/편집 화면의 상단 오른쪽에 닫기 버튼이 있는가
- 등록/편집 화면의 닫기 버튼은 부모 화면으로 돌아가는가
- 보험 등록/편집 화면에 `액션` 타이틀이 남아 있지 않은가
- 관리하기의 전체 화면 목록이 기본 접힘 상태인가
- 문서함의 등록/이동 버튼이 보조 액션처럼 오른쪽에 정렬되어 있는가
- 문서함이 등록 화면이 아니라 조회/관리 화면으로 보이는가
- 보험 관리 상단 액션이 오른쪽 정렬되어 있는가
- 보험 문서 등록이 상단 주요 버튼이 아니라 보험 행의 문서 추가에서 진입하는가

## 4. 우측 패널 체크

- 우측 패널의 후보 정보가 최대 20건 구조로 보이는가
- 우측 패널에 페이지 영역이 있는가
- 전체 이력 보기가 우측 패널 상단에서 닫기 왼쪽에 있는가
- 전체 이력 보기가 패널 하단에 중복으로 남아 있지 않은가
- `+` 클릭 후 현재 화면을 유지하는 구조로 보이는가

## 6. 상태/메시지 체크

- 각 주요 화면은 필요한 Empty / Loading / Error 상태를 검토했는가
- Empty 상태는 없는 데이터와 다음 행동을 함께 안내하는가
- Loading 상태는 저장, 삭제, 완료, OCR 확인, 보험 찾기 같은 중복 클릭 방지 기준을 포함하는가
- Error 상태는 원인 후보와 사용자의 복구 행동을 안내하는가
- Success 메시지는 저장/수정/완료 대상을 짧게 말하되 민감정보 값을 반복하지 않는가
- Warning 메시지는 삭제, 닫기, 민감정보, OCR 미확정 같은 위험 행동 전에 검토되는가
- Confirm 메시지는 버튼 문구가 행동 기준으로 명확한가
- 홈/대시보드, 가족 관리/등록, 보험 관리/등록/상세, 보험 문서 등록, 문서함, 청구 시작, 청구 서류 등록, OCR 확인, 보험 찾기 결과, 진행 현황, 청구 완료, 이력 보기/상세, 분류/항목 관리 화면군에 상태/메시지 기준이 있는가
- 등록/편집 화면은 저장 성공, 저장 실패, 닫기 전 변경사항 확인 기준을 갖는가
- 삭제와 사용 중지 메시지를 같은 의미로 쓰지 않는가
- 연결 데이터가 있는 `FamilyMember`, `Policy`, `Category`, `CategoryItem`, `Tag` Candidate는 물리 삭제보다 사용 중지를 우선 검토하는가
- 삭제 요청 메시지가 `delete_requested` 후보 상태와 충돌하지 않는가
- 실제 삭제 가능 조건은 `Needs Decision`으로 남아 있는가
- 닫기 버튼이 있는 등록/편집/상세 화면은 변경사항이 없을 때 부모 화면으로 돌아가는 기준이 있는가
- 닫기 버튼이 있는 등록/편집/상세 화면은 변경사항이 있을 때 확인 메시지가 필요한지 검토했는가
- 닫기 전 확인 메시지의 버튼 문구는 `계속 작성`, `저장하지 않고 닫기`, `취소`처럼 행동 기준으로 검토되는가
- 실제 dirty-check 구현 기준은 별도 결정으로 남아 있는가
- OCR 후보값을 자동 확정값처럼 표현하지 않는가
- 사용자 확정값만 업무 객체에 반영된다고 안내하는가
- OCR 후보값이 보험 찾기나 지급 판단의 확정 근거처럼 표현되지 않는가
- OCR 원문 전체 저장은 기본 미저장 방향이며 예외 저장은 `Needs Decision`으로 남아 있는가
- 실제 가족 실명, 실제 보험사명, 실제 병원명 샘플을 쓰지 않는가
- 고유식별번호, 계좌번호, 카드번호, 증권번호 전체값을 저장/표시하지 않는가
- 파일명에 실제 가족 실명, 병원명, 보험사명, 주민번호, 증권번호 전체값, 진단코드 기반 개인 사례가 들어가지 않도록 안내하는가
- 파일명은 내부 식별자, 날짜 범위, 문서 유형 수준으로 제한하는 방향을 유지하는가
- 원본 파일명 보존 여부와 세부 마스킹 포맷은 `Needs Decision`으로 남아 있는가
- `14_claim_complete.html`은 청구 준비 흐름 완료로 표현되는가
- 청구 완료 화면이 보험사별 제출 완료, 심사 완료, 지급 완료를 암시하지 않는가
- 지급 결과는 `08_claim_submission.html` 또는 이력 화면에서 확인하는 흐름으로 분리되는가
