# Low-Fi 와이어프레임 V2 검토 기록

## 1. 목적

이 문서는 `design/wireframes/*.html` V2 개선 내용을 검토하기 위한 기록이다.

이번 작업은 app 개발이 아니다. 실제 기능 구현, DB 구현, OCR 구현, WPF/WinForms 구현, runtime scaffold 생성은 포함하지 않는다.

## 2. 변경 요약

| 화면 | V2 개선 내용 |
|---|---|
| `index.html` | 권장 검토 순서와 개발 전 검토 목적 추가 |
| `01_home_dashboard.html` | 현황 요약 중심에서 오늘 확인할 작업 큐 중심으로 변경 |
| `02_family_members.html` | 가족별 보험, 문서, 청구 사건, 확인 필요 건수 요약 강화 |
| `03_policy_list.html` | 등록된 보험과 반자동 등록 후보를 분리 |
| `04_policy_detail.html` | 보험 기본정보, 연결 문서, 담보 후보, 청구 연결을 한 화면에 배치 |
| `05_document_box.html` | 문서 유형별 정적 탭과 확장 문서 목록 추가 |

| `07_claim_case.html` | 진료 정보, 연결 문서, 청구 후보, 청구 진행 현황, 지급 결과 요약 추가 |
| `08_claim_submission.html` | 청구 상태와 지급 결과를 별도 패널로 분리 |

## 3. 표현 기준

- 지급 가능 여부를 확정하는 표현은 사용하지 않는다.
- `참고 후보`, `확인 필요`, `사용자 확인 필요`, `결과 대기` 표현을 유지한다.
- 실제 가족 실명, 실제 보험사명, 실제 병원명, 실제 진단코드 기반 개인 사례를 사용하지 않는다.
- 샘플 데이터는 `가족 A`, `보험사 A`, `병원 A`, `문서 A`, `청구 사건 A`, `담보 A`처럼 익명화한다.

## 4. 구현 금지 확인 기준

V2 와이어프레임 검토 시 다음 항목이 없어야 한다.

- `app/`
- `src/`
- `package.json`
- `tsconfig.json`
- JavaScript
- 외부 CDN
- 외부 CSS 링크
- 외부 폰트 링크
- `attachments/` 내부 파일
- `data/local/` 내부 파일

## 5. 다음 검토 포인트

- OCR 확인함의 3분할 구조가 실제 확인 업무에 충분한가
- 청구 사건 화면의 정보량이 과도하지 않은가
- 보험사별 청구 이력에서 청구 상태와 지급 결과가 혼동되지 않는가
- 청구 참고 조회 결과의 네 범주가 사용자가 결과 단정으로 오해하지 않게 보이는가
- 향후 WPF 데스크톱 앱으로 옮길 때 좌측 목록, 중앙 작업 영역, 우측 상세 영역 구조가 유지 가능한가
