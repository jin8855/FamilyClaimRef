# 33_UI_STATE_AND_CONFIRMATION_MESSAGE_GUIDE

## 1. Goal

V5.5 정적 와이어프레임과 최신 데이터 모델 기준을 바탕으로 화면 공통 상태와 확인 메시지 작성 기준을 정리한다.

이 문서는 구현 문서가 아니다. JavaScript, modal, toast, DB 저장 방식, OCR 구현 방식, 실제 개인정보 예시는 포함하지 않는다.

## 3. Scope

포함 범위:

- 빈 상태
- 로딩 상태
- 오류 상태
- 저장 성공 메시지
- 저장 실패 메시지
- 삭제 확인 메시지
- 사용 중지 확인 메시지
- 닫기 전 변경사항 확인 메시지
- OCR 확인 전 경고
- 민감정보/파일명 관련 경고
- 청구 완료 전 확인 메시지

제외 범위:

- JavaScript 구현
- modal 구현 코드
- toast 컴포넌트 구현
- DB 저장 방식
- OCR 구현 방식
- 실제 개인정보 예시

## 4. Common State Types

| 상태 유형 | 의미 | 사용 위치 | 표시 원칙 |
|---|---|---|---|
| Empty | 조회 결과나 등록 데이터가 없음 | 목록, 문서함, 이력, 보험 찾기 | 없는 데이터와 다음 행동을 함께 안내 |
| Loading | 조회/저장/OCR 확인 진행 중 | 조회, 저장, OCR 확인 | 중복 클릭 방지와 처리 대상 명시 |
| Error | 처리 실패 또는 조회 실패 | 전체 화면 | 원인 후보와 복구 행동 안내 |
| Success | 저장/수정/완료 성공 | 등록/편집/완료 화면 | 무엇이 처리됐는지 짧게 확인 |
| Warning | 삭제, 닫기, 민감정보, OCR 미확정 | 주요 위험 행동 전 | 결과와 되돌릴 수 있는지 설명 |
| Confirm | 사용자의 명시적 결정을 요구 | 삭제, 사용 중지, 닫기, 완료 | 버튼 문구를 행동 기준으로 명확화 |

공통 원칙:

- 메시지는 민감정보 값을 반복하지 않는다.
- 후보값과 확정값을 구분한다.
- 청구 가능, 지급 가능, 지급 완료를 확정하는 표현은 사용하지 않는다.
- `Needs Decision` 항목은 메시지 기준에서도 확정 정책처럼 표현하지 않는다.

## 6. Empty State Message Rules

빈 상태는 단순히 없음으로 끝내지 않는다.

작성 기준:

- 현재 없는 데이터가 무엇인지 말한다.
- 다음 행동을 안내한다.
- 실제 가족명, 실제 보험사명, 실제 병원명, 실제 진단명은 사용하지 않는다.
- 화면의 CTA 또는 다음 이동과 연결한다.

예시 문구:

| 위치 | 빈 상태 문구 기준 | CTA 후보 |
|---|---|---|
| 가족 관리 | 등록된 가족 표시명이 없습니다. 가족 표시명을 먼저 추가해 주세요. | 가족 등록/편집 |
| 보험 관리 | 등록된 보험이 없습니다. 보험 기본정보를 추가해 주세요. | 보험 등록/편집 |
| 보험 문서 등록 | 선택한 보험에 연결된 문서가 없습니다. 보험 문서를 추가해 주세요. | 보험 문서 OCR 확인 |
| 문서함 | 등록된 문서가 없습니다. 보험 문서 또는 청구 서류를 먼저 등록해 주세요. | 보험 문서 등록, 청구 서류 등록 |
| OCR 확인 | 확인할 OCR 후보값이 없습니다. 문서를 먼저 등록해 주세요. | 문서함, 문서 등록 |
| 보험 찾기 | 조건에 맞는 담보 후보가 없습니다. 검색 조건을 줄여 다시 확인해 주세요. | 청구 시작 |
| 이력 보기 | 조건에 맞는 이력이 없습니다. 검색 기간이나 태그 조건을 줄여 다시 확인해 주세요. | 검색 조건 변경 |
| 분류/태그 관리 | 등록된 분류 또는 항목이 없습니다. 기본 분류와 항목을 추가해 주세요. | 분류 등록, 항목 등록 |

## 7. Loading State Rules

로딩 상태는 처리 중임을 알리는 것뿐 아니라 중복 처리를 막는 기준도 포함한다.

| 처리 | 문구 기준 | 중복 처리 기준 | 비고 |
|---|---|---|---|
| 목록 조회 중 | 목록을 불러오는 중입니다. | 조회 버튼 반복 실행 방지 후보 | Empty와 Error로 분기 |
| 저장 중 | 입력한 내용을 저장하는 중입니다. | 저장/삭제/완료 버튼 중복 클릭 방지 | 저장 대상은 화면명으로 보조 설명 |
| OCR 후보값 확인 중 | OCR 후보값을 확인하는 중입니다. | 확정 버튼 중복 클릭 방지 | 후보 계산이지 확정 판단이 아님 |
| 보험 찾기 결과 계산 중 | 입력 조건으로 담보 후보를 계산하는 중입니다. | 보험 찾기 버튼 중복 클릭 방지 | 지급 가능 확정 표현 금지 |
| 유사 청구 Top 3 조회 중 | 과거 유사 청구 후보를 조회하는 중입니다. | 더보기 반복 실행 방지 후보 | 결과는 참고 후보 |
| 청구 완료 처리 중 | 청구 준비 완료 상태로 정리하는 중입니다. | 완료 버튼 중복 클릭 방지 | 지급 완료 아님 |

## 8. Error State Rules

오류 메시지는 사용자 행동이 가능한 방향으로 작성한다.

| 오류 유형 | 표시 문구 기준 | 사용자 행동 | 비고 |
|---|---|---|---|
| 필수값 누락 | 필수 입력값을 확인해 주세요. | 누락 필드로 돌아가기 | 민감정보 값을 메시지에 반복하지 않음 |
| 저장 실패 | 저장하지 못했습니다. 입력값을 확인한 뒤 다시 시도해 주세요. | 다시 저장, 취소 | 원인 상세는 내부 로그 후보 |
| 조회 실패 | 목록을 불러오지 못했습니다. 조건을 줄이거나 다시 시도해 주세요. | 재조회 | 외부 API 호출을 전제하지 않음 |
| 문서 파일 접근 실패 | 문서 파일을 확인하지 못했습니다. 파일 위치와 연결 상태를 확인해 주세요. | 문서 재연결 | 원본 파일명 노출 주의 |
| OCR 후보값 생성 실패 | OCR 후보값을 만들지 못했습니다. 직접 입력하거나 문서를 다시 확인해 주세요. | 직접 입력, 문서 확인 | OCR 구현 지시 아님 |
| 보험 찾기 실패 | 보험 후보를 계산하지 못했습니다. 입력 조건과 연결 문서를 확인해 주세요. | 조건 수정, 문서 확인 | 지급 가능 확정 금지 |
| 유사 청구 조회 실패 | 유사 청구 후보를 조회하지 못했습니다. 조건을 줄여 다시 확인해 주세요. | 조건 수정, 재조회 | 검색 결과는 참고 후보 |
| 민감정보 규칙 위반 | 저장할 수 없는 민감정보가 포함되어 있습니다. 마스킹하거나 제거해 주세요. | 값 수정 | 구체 값 반복 금지 |
| 파일명 규칙 위반 | 파일명에 민감정보 단서가 포함될 수 있습니다. 내부 식별자와 문서 유형 기준으로 바꿔 주세요. | 파일명 수정 | 원본 파일명 보존 여부는 Needs Decision |

## 9. Save / Update Success Message Rules

성공 메시지는 무엇이 처리됐는지 짧게 말하되 민감정보 값을 반복하지 않는다.

| 대상 | 성공 메시지 기준 | 금지 표현 |
|---|---|---|
| 가족 등록/수정 | 가족 표시명 정보가 저장되었습니다. | 실제 이름 반복 |
| 보험 등록/수정 | 보험 기본정보가 저장되었습니다. | 실제 보험사명 또는 증권번호 전체값 반복 |
| 보험 문서 연결 | 선택한 보험에 문서 연결 정보가 저장되었습니다. | 원본 파일명 전체 반복 |
| 청구 사건 저장 | 청구 시작 입력값이 저장되었습니다. | 진단명, 병원명 반복 |
| 청구 서류 연결 | 청구 사건 후보에 서류 연결 정보가 저장되었습니다. | 원본 파일명 전체 반복 |
| OCR 후보값 확정 | 확정한 값만 청구 정보에 반영되었습니다. | OCR 후보값이 자동 확정됐다는 표현 |
| 분류/항목 등록/수정 | 관리 항목이 저장되었습니다. | 개인 사례 연결 표현 |
| 이력 메모 저장 | 이력 확인 메모가 저장되었습니다. | 청구 결과 확정 표현 |
| 청구 완료 | 청구 준비 흐름이 완료되었습니다. | 보험사 제출 완료, 지급 완료 암시 |

## 10. Delete / Disable Confirmation Rules

삭제와 사용 중지는 반드시 분리한다.

기준:

- 연결 데이터가 있는 항목은 물리 삭제보다 사용 중지를 우선 검토한다.
- 삭제 요청은 `delete_requested` 후보 상태와 연결한다.
- 실제 삭제 가능 여부는 `Needs Decision`으로 남긴다.
- 메시지는 연결된 보험, 문서, 청구 이력이 있을 수 있음을 안내한다.

| 대상 | 사용 중지 메시지 | 삭제 요청 메시지 | 제한 조건 | 데이터 모델 상태 |
|---|---|---|---|---|
| `FamilyMember` | 이 가족 표시명을 사용 중지하시겠습니까? 기존 보험과 청구 이력은 유지됩니다. | 이 가족 표시명 삭제를 요청하시겠습니까? 연결된 보험, 문서, 청구 이력이 있으면 제한될 수 있습니다. | 연결된 보험/청구 이력 | `disabled`, `delete_requested` |
| `Policy` | 이 보험을 사용 중지하시겠습니까? 기존 문서와 이력은 유지됩니다. | 이 보험 삭제를 요청하시겠습니까? 연결 문서와 청구 이력이 있으면 제한될 수 있습니다. | 연결 문서/청구 이력 | `disabled`, `delete_requested` |
| `Category` | 이 분류를 사용 중지하시겠습니까? 기존 항목과 이력 조건은 유지됩니다. | 이 분류 삭제를 요청하시겠습니까? 연결된 항목이 있으면 제한될 수 있습니다. | 연결 항목 | `disabled`, `delete_requested` |
| `CategoryItem` | 이 항목을 사용 중지하시겠습니까? 기존 검색 조건과 이력은 유지됩니다. | 이 항목 삭제를 요청하시겠습니까? 기존 청구 조건에 쓰였으면 제한될 수 있습니다. | 검색 조건/이력 연결 | `disabled`, `delete_requested` |

버튼 문구 기준:

- 사용 중지
- 삭제 요청
- 취소

## 11. Unsaved Changes Close Confirmation Rules

등록/편집/상세 화면의 닫기 버튼은 변경사항 유무에 따라 다르게 안내한다.

대상 화면:

- `13_family_register.html`
- `12_policy_register.html`
- `17_policy_document_register.html`
- `07_claim_case.html`
- `18_claim_document_register.html`
- `06_ocr_review.html`
- `19_category_register.html`
- `20_category_item_register.html`
- `21_history_detail.html`

기준:

- 변경사항이 없으면 바로 부모 화면으로 돌아간다.
- 변경사항이 있으면 확인 메시지를 표시한다.
- 저장하지 않고 닫으면 입력값이나 확인 상태가 사라질 수 있음을 안내한다.
- 실제 dirty-check 구현은 이 문서 범위가 아니다.

메시지 기준:

> 저장하지 않은 변경사항이 있습니다. 계속 작성하거나 저장하지 않고 닫을 수 있습니다.

버튼 문구 기준:

- 계속 작성
- 저장하지 않고 닫기
- 취소

## 12. OCR Review Warning Rules

OCR 후보값은 자동 확정값이 아니다.

포함 기준:

- OCR 후보값은 사용자가 확인해야 한다.
- 후보값은 보험 찾기나 지급 판단의 확정 근거가 아니다.
- 사용자 확정값만 업무 객체에 반영된다.
- OCR 원문 전체 저장은 기본 미저장 방향이며 예외 저장은 `Needs Decision`이다.
- `OcrExtraction` 별도 객체 유지 여부는 `Needs Decision`이다.

문구 기준:

> OCR 후보값은 자동 확정값이 아닙니다. 확인한 값만 청구 정보에 반영됩니다.

> OCR 원문 전체 저장은 기본 저장하지 않는 방향입니다. 예외 저장 여부는 별도 결정이 필요합니다.

## 13. Sensitive Data and Filename Warning Rules

최신 데이터 모델 gap 기준을 반영한다.

포함 기준:

- 실제 가족 실명 사용 금지
- 실제 보험사명, 실제 병원명 샘플 사용 금지
- 고유식별번호, 계좌번호, 카드번호, 증권번호 전체값 저장 금지
- 파일명에 실제 가족 실명, 병원명, 보험사명, 주민번호, 증권번호 전체값, 진단코드 기반 개인 사례 포함 금지
- 파일명은 내부 식별자, 날짜 범위, 문서 유형 수준으로 제한
- 원본 파일명 보존 여부와 세부 마스킹 포맷은 `Needs Decision`

경고 문구 기준:

> 입력값에 민감정보가 포함될 수 있습니다. 실제 이름, 전체 번호, 실제 기관명은 저장하지 않도록 마스킹해 주세요.

> 파일명에 민감정보 단서가 포함될 수 있습니다. 내부 식별자, 날짜 범위, 문서 유형 수준으로 제한해 주세요.

## 14. Claim Complete Confirmation Rules

`14_claim_complete.html`은 청구 흐름 완료 화면이다.

주의 기준:

- `ClaimCase` 완료와 `ClaimSubmission` 완료를 혼동하지 않는다.
- 청구 사건 완료는 청구 준비 흐름의 완료다.
- 보험사별 제출/심사/지급 완료는 `ClaimSubmission` / `ClaimPayment` 흐름이다.
- 완료 메시지에서 지급 완료를 암시하지 않는다.

확인 메시지 기준:

> 청구 준비 흐름을 완료하시겠습니까?

보조 문구 기준:

> 보험사별 제출과 지급 결과는 진행 현황에서 계속 확인합니다.

버튼 문구 기준:

- 청구 준비 완료
- 계속 확인
- 취소

## 16. Risks

- 삭제와 사용 중지를 같은 메시지로 처리하면 데이터 보존 정책이 흐려진다.
- OCR 후보값을 확정값처럼 표현하면 미확인 정보가 업무 객체에 반영된 것으로 오해될 수 있다.
- 청구 완료 메시지에서 지급 완료를 암시하면 `ClaimCase`와 `ClaimSubmission` 경계가 깨진다.
- 파일명과 경로가 민감정보 저장면에서 빠지면 Git 제외만으로 위험을 줄이기 어렵다.
- Empty 상태가 다음 행동 없이 없음으로만 표시되면 사용자가 어느 화면으로 이동해야 하는지 알기 어렵다.

## 17. Recommendation

- 모든 등록/편집 화면은 저장, 삭제, 사용 중지, 닫기 메시지를 분리한다.
- OCR 관련 화면은 후보값, 사용자 확정값, 업무 객체 반영값을 문구에서 구분한다.
- 문서와 파일 관련 화면은 파일명 마스킹 경고를 별도 기준으로 둔다.
- 청구 완료 화면은 청구 준비 흐름 완료만 말하고 지급 완료를 암시하지 않는다.
- Empty, Loading, Error, Success, Warning, Confirm 문구는 화면별 데이터 객체와 연결해 작성한다.
