## F. Selected Candidate Summary

### F1. Architecture

- Selected candidate: reuse `DocumentRegistrationViewModel`, `DocumentRegistrationWorkflow`, coordinators, and storage boundaries.
- Product-only parallel workflow: rejected.
- View/code-behind direct file or JSON storage: forbidden.
- ProductShell and MainWindow retain separate registration ViewModel instances.
- Lower workflow and storage services remain shared within one composition graph.
- `IPolicyClaimStorageService` remains the target repository owner for pre-attachment active-target rechecks.

### F2. File Authority and Lifecycle

- App-managed copy becomes authoritative only after a successful registration.
- External absolute path is runtime-only and forbidden in durable metadata.
- Same-root staging and atomic final rename are candidates.
- Success requires final payload, Document metadata, and one active target link.
- Normal exceptions require synchronous compensation.
- The current contract is successful-return consistency, not crash-atomic consistency across payload and JSON stores.
- A crash after final move can leave an orphan final payload or an active Document without a link; startup recovery is deferred.
- Production-ready claims are prohibited until recovery is approved, implemented, and validated.

### F3. Validation and Duplicate

- Allowed extensions remain `pdf`, `jpg`, `jpeg`, `png`.
- Picker filter must match the lower allowlist.
- Candidate maximum is `25 MiB` (`26,214,400` bytes).
- Zero-byte, unreadable, reparse, changed, malformed, and signature-mismatch inputs are rejected.
- Selection opens the source read-only and computes a SHA-256 runtime snapshot.
- Registration compares staged payload SHA-256 with that selection snapshot; mismatch requires reselection.
- Length and last-write are auxiliary checks only. The selection hash and original source path are not durable metadata.
- Active duplicate key is `target kind + target ID + SHA-256`.
- Duplicate query plus registration for the same target/SHA-256 is serialized inside one process and exactly one concurrent attempt succeeds.
- Cross-process uniqueness is not provided; multi-process and production readiness remain on hold.
- No global deduplication or version model is introduced.

### F4. Product State and Copy

- Picker cancel preserves a prior valid file and other draft fields.
- Navigation preserves the in-memory draft.
- Reentry reloads targets and clears stale transient copy.
- Success clears file/document metadata and retains a still-active target.
- Recoverable failure preserves retry inputs.
- ProductShell never displays path, raw ID, hash, CLR type, or raw exception.
